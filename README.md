# myIPproxy

Локальный маршрутизатор трафика на Qt 6: SOCKS5/HTTP на `127.0.0.1`, правила по процессу, адресу и порту, цепочки прокси и DPI-щит до вашего сервера.

Программа не подключается к серверам Яндекса или другого имени из поля «прикрытие». Это имя попадает только в SNI ClientHello, чтобы фильтр провайдера увидел знакомый домен. IP-пакеты идут на адрес, который указан у прокси.

Перехват «всех программ без настройки», как у Proxifier через подписанный драйвер WFP, в эту версию не входит: такой драйвер нужно отдельно подписывать. Сейчас трафик попадает в маршрутизатор так:

- приложение само использует SOCKS `127.0.0.1:10800` или HTTP `127.0.0.1:10801`;
- либо включён системный прокси Windows (браузеры и программы, которые его уважают).

Имя процесса берётся из таблицы TCP по соединению к локальному прокси. UDP ASSOCIATE работает напрямую и через один SOCKS5 без щита.

## Сборка

Нужны Qt 6 (Widgets, Network) и OpenSSL из MSYS2:

```bat
build.bat
```

Проверка без окна:

```bat
set PATH=C:\msys64\mingw64\bin;%PATH%
build\myipproxy_tests.exe
```

## Щит

На машине, где крутится выход, включите «Принимать входящие соединения щита», задайте ключ и для удалённого доступа смените адрес с `127.0.0.1` на `0.0.0.0`.

В клиенте добавьте прокси типа **Shield (свой выход)** на этот адрес и порт, с тем же ключом и любым именем прикрытия (`ya.ru`, `mail.yandex.ru` и т.д.). Правило сверху таблицы направляет нужный процесс на этот прокси.

Пароли и ключ в `config.json` закрываются DPAPI текущего пользователя Windows.
